#### Change

- FrogBoard Teleoperation WebSocket Server & Serial PTY Bridge:
  - Implemented an asynchronous WebSocket server `server.py` running over TLS/WSS on port 9090, listening on `192.168.100.100` with domain certificates for `robotfrogboard.yoonzh.com` to interface with the FrogBoard mobile client web application `frogboard.yoonzh.com`
  - Created a non-blocking master/slave pseudo-terminal (PTY) proxy layer establishing virtual serial interfaces `/tmp/virtual_twist_tx` (downlink command sink for ROS 2) and `/tmp/virtual_twist_rx` (uplink telemetry source for ROS 2), retaining exclusive ownership of the real physical serial port `/dev/serial_twistctl` at 115200 baud
  - Implemented multi-master command arbitration and multiplexing logic:
    - Prioritizes mobile joystick commands over autonomous ROS 2 navigation commands whenever phone inputs are active or an arm/disarm sequence is pending
    - Transparently routes ROS 2 commands from `/tmp/virtual_twist_tx` to the STM32 when the mobile controller is idle or disconnected
    - Enforces UART idle frame gap protection between consecutive transmissions to prevent command frame merging and rejection by the STM32 parser
    - Generates a neutral 10 Hz heartbeat during idle periods to continuously feed the STM32 firmware's 250 ms serial watchdog without disarming the chassis
  - Developed motor arming, disarming, and telemetry synchronization logic `protocol.py`:
    - Formats downlink frames as `vcx=%.3f,wc=%.3f,en=<code>\n`
    - Safety arm pulse `en=2`: Requires an explicit phone enable toggle and near-zero velocity, repeatedly transmitted over an arming window to safeguard against dropped frames
    - Safety active brake & disarm `en=0`: triggered on falling edge when disabled, or automatically upon disconnection of the last active client
    - Decodes extended 19-field CSV feedback from the STM32 (16 telemetry floats + `ctrl_mode` + `ps2_key` + `ps2_connected`). Automatically clears mobile app enable status if the lower controller transitions to disabled mode
  - Added active mode supervision and real-time ROS 2 telemetry relay:
    - Regularly polls background launch processes and broadcasts active state changes
    - Enables bidirectional WebSocket messaging supporting launch execution, system status broadcasts, and real-time streaming of any ROS 2 topic over websocket
    - Implemented clean connection termination, safely disconnecting all client sessions via `make kill-phones`
  - Added unit test suite `test_protocol.py` validating the functions above
  - Created systemd unit `scripts/frogboard_server/frogboard.service` for server autorun

#### Reason

- Headless Field Operations & Teleoperation: Operating the robot outdoors previously required carrying out your laptop to send SSH commands. Frogboard allows to fully control the robot without the PS2 controller or a laptop, as it includes sending commands and seeing logs from the phone
- The robot camera was forever unused; this serves as a first step to start using the camera and providing a low latency platform for later tasks where we may integrate computer vision or fancy stuff
- Both the ROS 2 navigation stack (`serial_twistctl_node` / `serial_reader_node`) and the Frogboard server need access to the single STM32 serial interface `/dev/serial_twistctl`. A virtual PTY proxy with explicit command arbitration ensures conflict-free sharing, priority override for manual intervention, and proper UART idle gap timing
- The robot previously had no safeguards when a controller dropped its connection, which has resulted in crashing and getting damaged. So I added more rigorous conditions for allowing the motors to be armed(`en=2`) with STM32 watchdog heartbeats
- The rm-c board code in this main repository has not been synced for who knows how long, and my partner taught me what a submodule is, so I figured out this was the perfect time to delete that and get things properly organized

- Any mobile disconnect, manual PS2 brake, or communication timeout immediately disarms motors and brings the vehicle to a controlled stop

- The Makefile setup is now updated to resolve some issues I had when setting up this fork in the robot. Hopefully this means if anyone else needs to set it up again from zero, they won't deal with the dependency issues I had.
